이 문서는 지금까지 한 모든 작업(마크다운/임베딩/모델비교/버그수정/
파인튜닝비교)을 하나의 이야기로 엮어서, 숫자가 아니라 "체감"으로
승부하는 발표 구성입니다. 슬라이드 번호, 화면에 띄울 문구, 말할 대사
톤까지 구체적으로 적었습니다.

"헛소리 vs 정확한 답변"을 봤을 때 훨씬 크게 반응한다.


====================================================================
1막 [위기] — RAG가 필요 없어 보이는 문제
====================================================================

슬라이드 제목: "그런데... RAG가 진짜 필요한가요?"

내용:
- 교수님 피드백 인용: "GPT-4, Gemini 같은 대형 모델은 CATIA 매뉴얼
  내용을 이미 사전학습으로 알고 있을 가능성이 높다"
- 화면에 실제로 큰 모델(Direct LLM, RAG 미적용) 답변 하나 보여주기
  → 이미 그럴듯하게 잘 대답함 (Direct LLM F1이 이미 0.6~0.7대로
    나쁘지 않은 걸 보여주는 게 포인트)
- 대사 톤: "처음엔 저희도 이 질문에 막혔습니다. 이미 잘 아는데
  뭘 더 보여줘야 하지?"

→ 여기서 청중에게 "그럼 이 프로젝트 의미없는거 아냐?" 하는
  긴장감을 만드는 게 목적. 답은 다음 막에서 나옴.


====================================================================
2막 [반전 1] — 그래서 일부러 멍청한 모델을 썼다
====================================================================

슬라이드 제목: "방향을 바꿨습니다 — 일부러 '모르는' 모델을 골랐습니다"

핵심 표 (모델 크기별 RAG 효과, 마크다운+다국어 임베딩 고정, 5문항):

  모델        Direct(RAG X)   Strict RAG(RAG O)   격차
  Qwen 0.5B      0.6346            0.6518          +0.0172
  Qwen 1.5B      0.6336            0.7150          +0.0814
  Qwen 3B        0.6497            0.8228          +0.1731

  (참고: 0.5B는 "초기 RAG"(마크다운 이전, 멀티모달 로더) 기준으로는
   오히려 0.6018로 Direct보다 낮았음 — 이게 1막의 "위기"임. 마크다운+
   다국어 임베딩으로 개선한 뒤에야 Direct를 앞지름)

- 대사: "만약 GPT-4로 실험했다면 이 격차가 안 보였을 겁니다.
  일부러 CATIA를 잘 모르는 작은 모델을 써서, RAG가 있고 없고의
  차이를 극대화시켰습니다."
- 트릭 질문(존재하지 않는 가짜 기능) F1이 3B에서 **1.0000**(완전
  거절, 환각 0%) 나온 것 강조 — 이게 이 막의 하이라이트 숫자

→ "약한 모델을 쓴 이유"가 이 프로젝트 설계의 핵심 전략이었음을
  각인시키는 파트


====================================================================
3막 [몽타주] — 이것저것 다 해봤다 (근데 평균은 조금만 오름)
====================================================================

슬라이드 제목: "성능을 올리기 위해 시도한 것들"

빠르게 몽타주처럼 나열 (한 장에 다 넣거나 2장으로):

  ✅ PDF → Markdown 변환 (문서 구조 보존)
  ✅ 다국어 임베딩 교체 (한국어 질의 검색 개선)
  ✅ 얇은 이미지 청크 노이즈 제거
  ✅ 하이브리드 검색 (BM25 + 벡터)
  ✅ 검색 파라미터(top_k, 하이브리드 가중치) 스윕 튜닝
  ✅ Grounding Check (2차 근거 검증으로 환각 차단)
  ✅ 다른 모델 비교 (0.5B/1.5B/3B/7B/BGE-M3)
  ✅ LoRA 파인튜닝 시도

작은 개선폭 표 (일부러 "생각보다 안 오르네?" 느낌으로):
  - 마크다운 로더: +0.003~0.009
  - 다국어 임베딩: +0.01~0.05
  - 검색 파라미터 튜닝 (top_k 2/4/6/8 x 하이브리드 가중치 0.3/0.5/0.7,
    61문항 실측, **0.5B 모델 기준** — 3B 등 큰 모델에서도 같은 경향인지는
    미검증): 기본값(top_k=4, 벡터만) F1 0.7617 -> 최적값(top_k=4,
    hybrid_w=0.7) F1 0.7700, +0.0083 — 재학습 없이 설정값만 바꿔서
    얻은 개선이라 "비용 0"인 점이 포인트
  - 이것들 다 합쳐도 모델 크기 하나 바꾼 것(+0.17)보다 작음

  ⚠️ 주의: 위 5문항 벤치마크(마크다운/다국어/모델크기 비교)와 이 61문항
  벤치마크(검색 파라미터 튜닝)는 평가셋 크기가 달라서 절대 F1 값을
  서로 직접 비교하면 안 됨. 각 표 안에서만 비교할 것.

- 대사: "저희도 처음엔 당황했습니다. 이렇게 많이 했는데
  왜 평균 점수는 이만큼만 오르지?"

→ 여기서 일부러 "밋밋한 결과"처럼 보여줘서 다음 반전의 낙차를 만든다

4막 [반전 2] — 진짜 클라이맥스, 실제로 보여주면 다르다
====================================================================

슬라이드 제목: "숫자로는 안 보였던 것 — 실제 답변을 보세요"

*** 여기가 발표에서 가장 중요한 슬라이드입니다 ***

Before/After 답변 3연타 (한 장에 하나씩, 임팩트 있게):

--- 사례 1: 완전히 다른 개념으로 환각 ---
질문: "Generative Part Structural Analysis의 한계는?"
[RAG 미적용] "생성형 AI 모델의 데이터 의존성..." ← Generative를
              "생성형 AI"로 완전히 착각!
[RAG 적용]   "메시 제어가 매우 제한적이며 솔리드 형상에만 적용
              가능" ← 정답과 정확히 일치

--- 사례 2: 트릭 질문 ---
질문: "CATIA V5의 3D 퀀텀 머시닝 AI 가속 모드는?"
[RAG 미적용] "다음과 같은 방법으로 실행됩니다: 1. 설정..." ←
              존재하지 않는 기능을 그럴듯하게 지어냄
[RAG 적용]   "The provided manual does not contain this
              information." ← 정직하게 거절 (F1 0.6 → 1.0)

--- 사례 3: 파인튜닝을 점점 정교하게 해봐도 못 따라옴 (2단계 실험) ---
"그럼 파인튜닝하면 되지 않나?"를 두 단계로 검증:

  1단계 - 단순 암기 파인튜닝:
  [학습 안 한 질문] "Quantum Machining은... AI 기능입니다" ← 환각

  2단계 - 문맥까지 포함해서 "RAG 스킬" 자체를 학습시킴 (더 정교한 시도):
  [학습에 없던 트릭 질문①] "The provided manual does not contain
                this information." ← 이번엔 정확히 거절! (일부 성공)
  [완전히 새로운 화법의 트릭 질문②, "감정인식 설계"] "사용자가 감정에
                따라 설계를 결정하는 기능입니다..." ← 또 환각!

  → 파인튜닝을 아무리 정교하게 해도(2단계까지 가도) "비슷한 유형은
    막고 새로운 유형은 뚫리는" 반쪽짜리 방어에 그침

  [같은 질문들, RAG+grounding_check] 전부 정확히 거절 (100%)

- 대사: "저희는 파인튜닝을 2단계까지 발전시켜봤습니다. 그래도
  RAG처럼 매번 확인하는 방식의 신뢰도를 따라잡지 못했습니다."

- 대사: "평균 점수는 +0.05였지만, 실제로 이런 순간들이 쌓인
  결과입니다. 숫자보다 이 화면이 저희가 한 일을 더 잘 보여줍니다."

5막 [피날레] — 라이브 대시보드 시연
====================================================================

슬라이드 제목 없이 바로 화면 전환: "지금 직접 보여드리겠습니다"

시연 순서 (미리 연습해서 순서 외우기):
  1. Streamlit 대시보드 열기 (`streamlit run src/app.py`)
  2. 모델을 0.5B(가장 약한 모델)로 선택
  3. 질문 1 (일반 질문, 예: "Pad 기능이 뭐야?") → RAG 답변 정상 확인
  4. 질문 2 (트릭 질문, 예: "퀀텀 머시닝 AI 가속 모드는?") 라이브로
     타이핑 → 청중 앞에서 실시간으로 "매뉴얼에 없음" 거절 확인
  5. (여유 있으면) 같은 질문을 RAG Off로 바꿔서 비교 → 지어내는 걸
     라이브로 보여줌

주의사항:
  - 로컬 모델 로딩 시간이 있으니 발표 시작 전에 미리 한번 실행해서
    캐시/GPU 워밍업 해두기
  - 네트워크 끊길 경우 대비해 사례 스크린샷을 백업 슬라이드로 준비

"내가 한 것" 상세 목록 (개인 발표 파트/포트폴리오용)
====================================================================

아래는 담당(마크다운/임베딩 + 이후 확장)한 작업의 전체 타임라인입니다.
발표 대본이나 개인 기여도 슬라이드에 그대로 쓰실 수 있어요.

[구현한 기능]
- PDF → Markdown 변환 로더 (pymupdf4llm, 헤더/표 구조 보존)
- 다국어 임베딩 옵션 (paraphrase-multilingual-MiniLM-L12-v2)
- GPU 자동 감지 임베딩 (기존엔 CPU로 하드코딩되어 있던 것 발견/수정)
- 하이브리드 검색 (BM25 + 벡터, EnsembleRetriever)
- 얇은 이미지 청크 노이즈 제거 (_merge_thin_groups)
- RAG 프롬프트 언어 불일치 수정 (한국어 질문에 영어로 답하던 버그)
- LoRA 파인튜닝 vs RAG 비교 실험 (단순 암기 -> RAG-태스크 파인튜닝 2단계)
- 검색 파라미터(top_k, 하이브리드 가중치) 스윕 튜닝 자동화 스크립트

[발견하고 고친 버그]
- README.md git 병합 충돌 마커가 그대로 커밋되어 있던 것
- 임베딩 정규화 누락 (검색이 벡터 크기로 왜곡되던 심각한 버그)
- pdf_path/eval 경로가 상대경로라 src/에서 실행 시 깨지던 문제
- accelerate 패키지 누락으로 로컬 GPU 모델이 조용히 API로 폴백되던 버그
- vect/ 벡터DB가 git에 추적되고 있어 머지할 때마다 인덱스가 손상되던
  문제 (팀원이 먼저 발견한 걸 이 환경에서도 재현/검증)
- API 벤치마크가 결제 오류로 실패했는데 에러 메시지가 그대로
  채점되어 가짜 점수(F1 0.5998)가 나온 것 발견
- 검색 거리 점수로 환각을 걸러내려는 시도 → 역효과 확인하고 폐기
  (트릭 질문이 오히려 거리가 가까웠음)

[정량 실험]
- 모델 크기 비교: 0.5B(0.65) → 1.5B(0.72) → 3B(0.82) (5문항, 마크다운+다국어 고정)
- 임베딩 비교: 영어전용 → 다국어 (+0.01~0.05, 작은 모델일수록 효과 큼)
- 검색 파라미터 튜닝: top_k(2/4/6/8) x 하이브리드 가중치(0.3/0.5/0.7) 7개
  조합 스윕 (61문항, 0.5B) -> hybrid_w=0.7이 최적, F1 +0.0083
- 38문항 고난도 평가셋으로 팀원(Solar 평가)과 교차검증
- 파인튜닝 vs RAG 3-way 비교 (순수 암기 / RAG-태스크 학습 / RAG+grounding_check)

[브랜치 통합]
- main-test 브랜치를 만들어 팀원 5명 이상의 브랜치(wooryeol, KBU,
  jaeyoung 등)를 순서대로 병합, 충돌 다수 수동 해결
- 각 병합마다 실제 파이프라인 스모크 테스트로 정상 동작 검증

이 목록 자체가 "짧은 시간에 얼마나 많은 실험/문제해결을 했는가"를
보여주는 근거이니, 발표 자료 분량이 부족하면 이 목록에서 항목별로

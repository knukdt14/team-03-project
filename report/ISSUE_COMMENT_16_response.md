# 이슈 #16 대응 결과 정리

Racoon7828님이 정리해주신 3가지 이슈 각각 시도해본 결과 공유합니다. (`main-test` 브랜치, 커밋 `0249e89`)

## 1. 얇은 이미지 청크 노이즈 → ✅ 해결

`src/load_pdf.py`에 `_merge_thin_groups()` 추가. 텍스트가 40자 미만인 제목/캡션뿐인 청크(예: "3) Concentricity"만 있고 실제 정의는 스크린샷 이미지 안에만 있는 경우)를 다음 청크와 자동 병합해서, 정보량 없는 청크가 검색 상위에 혼자 뜨는 문제를 완화했습니다.

- 실측: `CATIA V5 Lectures.pdf` 기준 최소 청크 텍스트 길이가 67자로 개선됨 (기존엔 더 짧은 제목뿐인 청크 존재)
- 다만 이건 OCR이 아니라 "혼자 뜨지 못하게 합치는" 수준의 완화책입니다. Racoon7828님이 진행 중이시라는 OCR로 이미지 텍스트 자체를 뽑아내는 방향이 근본 해결책이고, 이 병합 로직과 **서로 상충하지 않고 같이 쓸 수 있습니다** (OCR로 텍스트를 채운 뒤에도 여전히 짧은 청크가 남으면 이 로직이 마저 병합해줌).

## 2. 소형 모델(0.5B) 환각, Adaptive Fallback 미작동 → ❌ 시도했으나 실패, 비활성화

검색 결과의 유사도 거리 점수를 이용해서 "문서를 찾긴 했지만 실제로 무관한" 경우를 걸러내려 했습니다 (`top_retrieval_distance` 계산 후 임계값 초과 시 강제 폴백).

**실측 결과 역효과를 확인해서 비활성화했습니다.** 트릭 질문과 정상 질문의 거리를 직접 비교해보니:

| 유형 | 질문 | 거리 |
|---|---|---:|
| 트릭 | 자율주행 홀로그램 | 0.43 |
| 트릭 | 뇌파 인식 스케치 | 0.64 |
| 트릭 | 블록체인 이력관리 | 0.59 |
| 정상 | Rib/Slot 차이 | 0.74 |
| 정상 | Chamfer 사용시점 | 0.95 |
| 정상 | 동심원 구속조건 | 0.90 |

**트릭 질문이 오히려 거리가 더 가깝게 나옵니다.** 이 임베딩 모델(`paraphrase-multilingual-MiniLM-L12-v2`)로는 거리 점수만으로 "관련 있음/없음"을 구분할 수 없다는 뜻이라, 이대로 배포하면 정상 질문을 잘못 걸러내고 트릭 질문은 통과시키는 역효과가 납니다.

`config.py`의 `RETRIEVAL_DISTANCE_THRESHOLD`를 `inf`로 설정해 자동 트리거는 비활성화했고, 거리 값 자체는 진단용으로 계속 기록만 하도록 남겨뒀습니다. **다른 접근이 필요합니다** — 예: 검색된 문서 원문과 질문 사이 키워드 중첩 체크, 또는 LLM한테 "이 문맥에 답이 실제로 있는지"를 별도로 한 번 더 검증시키는 단계 추가.

## 3. 청킹/임베딩 튜닝만으로 안 풀리는 근본적 검색 실패 케이스 → 🟡 부분 개선

`src/vector_store.py`에 `get_hybrid_retriever()` 추가 (BM25 키워드 검색 + 벡터 검색을 `EnsembleRetriever`로 결합). `RAGPipeline(use_hybrid_search=True)`로 켤 수 있고, 기본값은 `False`라 기존 동작에 영향 없습니다.

실측 결과:
- **질문에 영어 기술용어가 섞이면 도움됨**: "CATPart 확장자가 뭐야?"처럼 질문에 정확한 키워드가 있으면 벡터 검색만으로도 이미 정답 근처 문서를 찾고, 하이브리드가 관련 문서를 더 추가해줌
- **순수 한국어 질문 vs 순수 영어 매뉴얼처럼 겹치는 단어 자체가 없으면 하이브리드도 한계**: BM25는 어휘가 실제로 겹쳐야 작동하는데, "확장자"(한국어)와 ".CATPart"(영어)처럼 아예 다른 언어면 BM25도 못 찾음. 오히려 무관한 한국어 강의자료 텍스트("실습5" 등)를 노이즈로 더 끌고 오는 경우도 확인됨

**결론**: 이 이슈에서 지적하신 근본적 검색 실패 케이스는 청킹/임베딩/BM25 튜닝 중 어느 것으로도 100% 해결이 안 됩니다. 진짜 해결하려면 쿼리 자체를 영어로 번역/확장하는 단계(이미 있는 `expand_query()`를 더 강화)나, 리랭커(cross-encoder) 도입을 다음으로 검토해야 할 것 같습니다.

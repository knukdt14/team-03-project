# RAG 검색 최적화 중간 보고

## 목표

최종 선정될 LLM에 RAG를 결합했을 때 CATIA 매뉴얼 기반 질의응답의 정확도와
근거성을 높일 수 있도록, 재현 가능한 검색 파라미터 조합을 찾는 것이 목표입니다.

## 초기 실험과 판단

초기에는 청크 크기, overlap, Chroma 검색 방식, `top_k`, 프롬프트, BM25,
Hybrid RRF, reranker를 비교했습니다. 그러나 청크 크기만 바꾼 경우 개선 폭은
작았습니다. MiniLM 기반 Chroma MMR 500과 800의 F1은 각각 `0.7460`,
`0.7468`이었습니다. BM25와 reranker는 품질을 높이지 못하거나 응답 시간을
크게 증가시켜 채택하지 않았습니다.

| 설정 | F1 | 평균 응답시간 |
|---|---:|---:|
| MiniLM + Chroma MMR 500 | 0.7460 | 0.78초 |
| MiniLM + Chroma MMR 800 | 0.7468 | 0.77초 |
| Hybrid RRF 500 | 0.7409 | 0.74초 |
| Reranker 500 | 0.7254 | 7.66초 |

따라서 무작위 파라미터 확장 대신, 검색 품질과 검색 실패 사례 분석 중심으로
방향을 전환했습니다.

## 개선 작업

평가 문항을 10개에서 40개로 확장하고, 매뉴얼에 없는 질문도 포함했습니다.
각 결과는 BERTScore, 응답시간, RAGAS Faithfulness, 수동 환각 검토로 평가합니다.

핵심 개선은 MiniLM을 다국어 임베딩 모델 BGE-M3로 교체한 것입니다. Chroma,
500/100 청크, MMR, `top_k=6`, strict prompt 조건은 유지했습니다.

| 설정 | F1 | Faithfulness | 평균 응답시간 | 수동 환각률 |
|---|---:|---:|---:|---:|
| MiniLM + Chroma MMR 500 | 0.7460 | 0.6893 | 0.78초 | 7.5% |
| BGE-M3 + Chroma MMR 500 | **0.7597** | **0.7737** | 0.88초 | 7.5% |

수동 검토에서는 40개 중 3건을 환각으로 판정했습니다. 도면 확장자를 잘못
답한 사례, `New Body` 대신 `Open Body`를 답한 사례, IGES/STEP의 용도를
근거 없이 내보내기라고 답한 사례입니다.

## 현재 선두 설정

- `BAAI/bge-m3` 임베딩
- Chroma 벡터 DB
- chunk 500 / overlap 100
- MMR, `top_k=6`
- 문서 근거 기반 strict prompt + 출처 표기

## 다음 개선 실험

남은 검색 실패를 줄이기 위해 한국어 원 질의와 간결한 영어 검색 질의를 함께
사용하는 한·영 이중 질의 검색을 실험합니다. F1 `0.78 이상`, Faithfulness
`0.77 이상`, 수동 환각률 `7.5% 이하`, 평균 응답시간 `1초 내외`를 통과 기준으로
둡니다. 이후 최종 LLM에서 LLM 단독과 LLM+RAG를 같은 평가셋으로 비교합니다.
